# Ghost Node Pool: build plan

Companion to `NODE_POOL_SPEC.md`. Simulations, the firmware research and the hardware test kit live outside the repo for now; paths starting `sims/` or `hardware-test/` are relative to that working folder.

## Approach change, 11-02: rip out, flag-day cutover

This branch strips the old system out as it builds the new one. It does not keep old code dark beside new code.

- **Cutover is a flag day.** At an agreed block every node switches to the new binary. Before it, the current release exports the miners' ledger balances (one small export command added to main), and the new binary imports them as its genesis table, pinned by digest. The new binary contains none of the old payout, checkpoint, elder or capability code.
- **Old tables are dropped** by the migration that imports the genesis table.
- **Activation gates** (`u64::MAX`) added in W2.1-W2.4 become network configuration for regtest and signet, and are removed for mainnet once the flag day is set.
- **Removal waves**, on this branch, each leaving the workspace building and tested:
  1. Wraith (wallet app, coordinator, protocol), Ghost Tap, ghost-lock and its signer, and anything reachable only from them.
  2. zk, MPC, L2 and glyph, with the zk start gate and the `zk-production` build feature.
  3. With W2.6/W2.7: the old payout ledger, checkpoints and votes, elders, capabilities and challenges, fee drift, solo and private modes, the job-declaration path, old tables. Code removed and merged 11-02 (`95aa0d48e`); the tables stay until migration v65 imports the genesis table. ghost-miner-proxy went with the elder-signed node-list checkpoint it verified; W2.9/W2.10 rebuild the miner-side tool against open listing.
  4. ~~ghostd to stock Bitcoin Core~~ CANCELLED 11-02 (user): **ghostd stays.** Node pool nodes run on ghostd, with Reaper, BUDS, Haze, Shroud and its other features. The dashboard, docs and website overhauls are W2.14-W2.16.
- Phase 4's Release A / Release B dual running is replaced by this. Phases 3 (regtest, signet) still come before any mainnet use.
- **Side by side, 11-02 (user):** the node pool launches on its own servers beside the old 8-node fleet, which keeps running main until the handover. The two networks share nothing: the node pool has no MPC, elders, votes or old mesh seeds, and its share chain runs on its own relay port and protocol. Never co-host both on one server (same unit names, paths and ports). Miners move by repointing; their old balances arrive through the genesis table.
- **Old fleet with 4 nodes:** checkpoint quorum is 67% of a voter set that never drops below the 8 elders, so with only vm1-4 running no checkpoint finalises again (read from `payout_checkpoint.rs` on main, not observed). Mining continues; the old ledger's agreed record freezes. Back up the databases of any node before it is switched off: they feed the genesis comparison and hold the MPC lineage.

**Signet harness, BUILT 11-02 (`feat/node-pool-signet`, not merged).** `scripts/regtest-node-pool/run.sh --network signet` (scenarios in `scenarios_signet.py`, sharing the regtest harness's code): 4 nodes, each ghostd (the released v1.11.46, Reaper on) + ghost-mining + pool_sv2 with its relay + translator, peered only with each other, on a custom signet of the run's own. Findings and choices:
- **The challenge cannot need a signature.** A signet block signature commits to the merkle root, so to every extranonce a miner rolls; no pool can hand out a signed job. The harness's challenge is `<32-byte network id> OP_DROP OP_TRUE` (an empty solution passes, as `signet.cpp` allows for OP_TRUE), with a fresh id per run, so the network's message start, and so its peers, are the run's alone. A keyed challenge would need a signer inside the pool per share; for the hardware stages, the same trivial challenge with our own id is the practical choice.
- **Tier base.** Signet's minimum difficulty is about 4.8M hashes. The harness sets `tier_base` to 2^17 x signet's proof-of-work limit, so the network tier is easier than a block and the anchor tier half a block's target: every block is a network share, half are anchors, and pool_sv2's channel floor (difficulty 2^10) keeps everything else off the relay, as on regtest. Miners grind natively (`grind.c`).
- **Genesis rehearsal.** Export at height 30 (the freeze), genesis anchor there, ghostd mines plain blocks to 50 (the Phase 4 rule: 20 blocks before miners are repointed), every node imports, verifies and pins one root, and no work is void.
- **A 500-payee coinbase exists only while the snapshot is the genesis table.** On a low-difficulty chain one share credits far more than a block pays, so once miners' credits reach a snapshot (20 blocks after their first share) every block pays them and the genesis table only fills the oldest half. Full-class miners climb the slot classes in that window (3, 9, 44, 143, 364, then 500).
- **Measured, two full runs (1,200 and 4,000 genesis rows), every scenario PASS:** the 503-output coinbases (no fees, so no finder output) equal `refimpl_v3.py`'s byte for byte, 250 oldest + 250 largest, treasury = S/200 + change, and settle on every node; every genesis-only block (classes 3 to 500) is exact against the reference; 90 pool wins on demand from all four nodes, one ledger digest on every node; every genesis row at or above 1,000 sats paid in full once and none below it; a 4-block reorg across 4 pool blocks undone and redone to identical digests; a fresh node synced to identical digests; five hostile builds (wrong treasury, fee skim, payees out of order, ledger commitment left out, one payee overpaid) refused by name on every honest node, never credited, and failed by `ghost-audit` with the matching reason.
- **Sensing finding, decided by the user 2026-11-03.** A settled miner that stayed connected but sent no valid share past the no-share timeout lost its class, one class per timeout, and the lost class was never retried that session (`slot_class_sensing.rs`, `tick`): seen when the harness paused miners between phases (full-class miners fell from 500 to 364, one to 143). Decision: once shares resume the class is sensed again and may climb back up; a miner that really lost hashrate still settles lower, one that only stalled recovers; disconnects unchanged. Fixed on `feat/node-pool-resense`: silence after settling still drops one class per timeout, but the class is suspended (`cause=Stalled`), not failed; the first valid share after a stall starts re-sensing at the class it fell to (no dwell; silence there suspends again), and the climb back uses the ordinary trial rules, so a trial that fails (low yield, silence, a corrupt or stale share) fails for good and the miner settles below it. Silence during a trial still fails that class. Every change still needs a timeout of silence or `min_shares` valid shares, so sensing stays deterministic and moves only on events. Unit tests: stall then resume at full rate returns to 500, resume slower settles lower with one failed trial and no change in an hour more, five stall/resume cycles recover identically. The harness's slot-class scenario no longer allows a silent drop: it resumes the miners and requires every one back at its class and settled.
- **No ledger commitment.** A block on one of our anchors with the `GHNP` output left out retired nothing but was skipped silently; settlement now names it and counts it as mismatched (state unchanged).
- **Not covered (then):** the 24 h soak, a share-chain (not Bitcoin) partition, hardware, release builds.

**Partition, lying sync peer, soak, release build: 2026-11-03 (`feat/node-pool-resense`, not merged).** New scenarios in `scenarios_resilience.py`; measured on our signet with ghostd v1.11.46.

### Phase 4: cutover (flag day)
- **Launch beside the old fleet.** The node pool runs on its own servers; the old 8 keep running main, untouched, until the handover.
- **Freeze.** At an agreed height the old release stops crediting work. Each old node finishes syncing to that height.
- **Export** (`feat/ledger-export`, on main): every old node exports its balances at that height, read-only. Open (user, 11-02): export from the full shard balance table rather than a checkpoint, because checkpoints since 963,388 hold only the top 200 and a checkpoint's stored root matches its miner list at only ~2% of heights.
- **Compare.** All exports should give the same digest. If they differ, a fixed rule settles each differing miner (for example the median) and the differences are published.
- **Pin and import.** Convert work to sats at one published rate (the user's call), pin the table digest in the node pool binary, publish the table. Migration v65 imports it as the genesis table and drops the old tables; it halts on non-zero rows in `withdrawal_requests`, `ghost_locks`, `l2_*`, `wraith_*`. Rehearsed on database copies first. BUILT 11-02 (`feat/node-pool-v65`, not merged): migration v65 drops the old tables (halts on those rows, takes and verifies a `VACUUM INTO` copy first, stores the version negated so older binaries refuse the database) and creates `np_genesis`; `pool_sv2 --np-import-genesis DIR --np-export-digest HEX` imports the export into the relay's store, sets `queue_since` to the export height at or above the floor, and prints the `table_root` to pin. Readings in `node-pool-reference/PORTING_NOTES.md`. Waiving balances is out: the website says work "never expires".
- **Genesis anchor at least 20 blocks before launch (operational rule, Phase 3 finding E; signed off 2026-11-02).** A share of job height `H` is paid from the last anchor below `cut(H) = H - 20`, and the first anchor is the genesis anchor, so work on heights up to genesis + 20 earns nothing (rule 6 has no snapshot anchor). Nodes still serve jobs there (a block found is valid and pays the genesis table), log `NODE_POOL_VOID_WORK` per height, refuse to make an anchor of such a share, and the status, miner page and dashboard say "earns nothing until height genesis + 21". So set the mainnet genesis anchor's `btc_height` at least 20 blocks before the height miners are repointed: no live work is then void.
- **Rehearsed end to end, 2026-11-03** (`feat/node-pool-flagday`, `docs/FLAG_DAY_RUNBOOK.md`): old-format v62 databases written by main's own code, exported by the real exporter (identical digests across copies and node keys), migrated by v65 inside each of 4 signet nodes, imported and paid out exactly (16/16 harness PASS). Found and fixed: v65 refused only after v63/v64 had committed (left at v64, no copy); the import accepted P2PKH rows the coinbase must not pay (now refused, a decision: section 5); the exporter now names a migrated database. Measured: the checkpoint source carries only the top 200 (55-60% of owed work on the rehearsal population).
- **Repoint miners** to the node pool. The old fleet is switched off only after its databases are backed up.
- **Ninth node:** an outside operator, public docs only, must reproduce the root, get its miner credited and have its cheat refused.
- **Rollback:** before the import, keep running the old fleet. After it, forward fixes only.

Order of publication: spec, export digest and table, notice of the freeze height, installer docs, payout text, retire old docs after the handover.

## 6. Open design items for spec freeze
- **SV2 standard channels are allowed (decided 11-02).** An SV2 miner on a standard channel receives only a header, so it always gets the full 500-output class. W2.3 must stamp the per-channel tag in the pool-built coinbase.
- Change goes to the treasury (decided 11-02). Known low-limit SV1 firmware gets a warning at connect and on the miner page, naming the model and the expected cost; it is not refused.
- Sub-NS credit for small miners above about 1 EH/s: at 100 EH/s, 85% of 1.2 TH/s miners earn nothing in a month.
- The table root goes in one OP_RETURN output (`x` no longer exists). ScriptSig is 99/100 full, so the coinbase carries 504 outputs at most.
- Cost of the 90,000 WU reserve: about 20,500 vB of block space, roughly 20,500 sats per full block at 1 sat/vB, or 1.2% of the average fee. Estimate, not measured. It falls on the finder, and every template pays it whatever the slot class.

## 7. The honest reading
Protocol work makes the pool safe. It doesn't create hashrate. Median days to first payment, simulated under the draft 6 floating rule, Bitaxe / 100 TH/s. Exact payment will change these; W1.3 reruns them:

| Pool share of network | Blocks every | Large coinbases, 250 + 250 | Large coinbases, 100 + 400 | Large coinbases, 450 + 50 | Low-limit Mix B, 250 + 250 |
|---|---|---|---|---|---|
| 1% (10.7 EH/s) | 17 hours | 153 / 136 | 470 / 409 | 82 / 66 | About half not paid in 2 years |
| 5% (53 EH/s) | 3.3 hours | 111 / 43 | 141 / 73 | 94 / 26 | 306 / 226 |

"Large coinbases" here means 340 outputs per block, so 170 oldest at 250 + 250; a true 500-output block should do better but was not run. The 250 + 250 and 100 + 400 runs used 2 seeds each and are a quick read. Mix B is 50% of the hash at 40 outputs, 30% at 12 and 20% at 340, using the same rule on every block. With 80% at 12 outputs (Mix C), 73-77% were not paid in 2 years at 1% of the network. 4% of Bitaxes at 1%, and 20% at 5%, were not paid within the run even on large coinbases. The 0.1% case was not rerun; at 450 + 50 it took 1,127 / 1,091 days on large coinbases.

So the first useful audience is node runners and larger miners, and only on firmware with room for large coinbases. Home miners become a real audience only near 1% of the network. Demand testing with real miners remains unfinished and doesn't depend on any of this engineering.
