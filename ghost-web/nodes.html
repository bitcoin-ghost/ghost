Run a node pool node.

Anyone can run one, without asking. Your node builds its own block templates, serves its own miners and keeps the same ledger as every other node. When one of its miners finds a block, the block's transaction fees are yours.

Deployment guide → Node list
what a node gets

Fees from your own miners' blocks. Nothing for being up.

A node's income is the transaction fees of every block its own miners find, paid to its fee address. Miners are paid separately, from the subsidy, by the ledger. A node with no miners earns nothing.

There are no node rewards, capabilities, elders or uptime requirements any more. Those belonged to the old network and are removed.

Running your own node is also the one sure way not to be cheated by a node: a node builds its miners' jobs, and until ghost-audit exists, a miner on someone else's node is trusting it.

before you start

What you need.

ComponentMinimumRecommended
CPU4 cores8+ cores
RAM8 GB16+ GB
Storage500 GB SSD1 TB NVMe
Network100 Mbps symmetric1 Gbps
Linux x86_64, Ubuntu
The installer runs as root, uses apt-get and ufw, and refuses anything that isn't x86_64.
A fee address
--fee-address: P2SH, P2WPKH, P2WSH or P2TR on the node's network. P2PKH is refused, and a bad checksum is refused rather than paid.
An alert endpoint
Optional, for example https://ntfy.sh. Without one, alerts for low disk, node offline and restart loops fire into nothing.
Relay peers
Optional: --relay-peer host:port, repeatable. Without any, the node waits for peers to dial it on the relay port, 8566.
SSH on port 22, or a rule first
The installer enables ufw and only allows SSH on 22. If yours is elsewhere, add the rule before you install.
A server of its own
Never run a node pool node on the same server as an old-network node: they use the same unit names, paths and ports.
install

One command, once there is a release.

curl -sSL https://get.bitcoinghost.org | sudo GHOST_VERSION=<node pool release tag> bash -s -- \
  --fee-address bc1q… \
  --alert-webhook https://ntfy.sh

No node pool release has been published yet. Every release on GitHub so far belongs to the old network, so the installer refuses to run without GHOST_VERSION naming a node pool release.

No share-chain genesis is published for mainnet or signet. Until one is, the pool refuses to start on those networks; regtest works for testing.

The installer verifies the release signature, generates every key on the machine, keeps the node off the old network, and leaves automatic updates off. Everything it does →

being listed

Open listing. No approval.

Any node with a valid advert that passes an outside probe will appear on the node list. There is no roster and no signed list. The listing service is not built yet; until it is, the node list shows a placeholder.

read this first

Before you run a node.

  • No block has ever been found by the node pool.
  • No payout has ever been made.
  • Your balance may stay unpaid for a long time.
  • An unaudited node can cheat you. The tool to audit one, ghost-audit, is not built yet.
  • If you need steady income, use an established pool.
