# Ghost mining-discovery shim — GENESIS SIGNER SET
#
# The node ids a freshly-installed `ghost-miner-proxy` trusts on first run. One hex node id per
# line; blank lines and `#` comments are ignored. Pass with `--genesis-file`, or inline the same
# ids with `--genesis-signers`.
#
# WHAT THIS IS FOR
#
# Miners currently find the pool through one DNS name. That is a single point of control: if the
# name is seized, misdirected, or simply goes down, every miner loses the pool at once. The shim
# removes that dependency by carrying its own list of pool nodes.
#
# A list the miner holds locally is only as good as its provenance, so the list is signed and the
# shim accepts a new one only when >=67% of the signers it ALREADY trusts have signed it. Which
# means it has to start out trusting someone — this file.
#
# THRESHOLD ARITHMETIC (read before changing the number of entries)
#
#   signers n = 12   (8 fleet nodes + 4 offline-only keys)
#   required  = ceil(n * 67 / 100) = ceil(8.04) = 9
#
# So 9 of these 12 must sign to move the set forward. Two consequences, both permanent:
#
#   * Lose 4 keys and the set FREEZES. Anyone already running the shim keeps dialling whatever
#     nodes were last attested, forever, because 9 signatures can never again be assembled.
#     At most 3 may be lost.
#   * Whoever controls 9 keys can point every shim-using miner anywhere they like, and the shim
#     sees a perfectly valid update.
#
# WHY 4 OFFLINE KEYS AND NOT 3
#
# An earlier draft said "hold 3 of the 8 fleet keys offline". That was wrong on its own premise. The
# 8 fleet ids below ARE the nodes' operational identity keys (`node.key`), used at 32 signing sites
# for mesh messages, votes, health pings and checkpoints. A node cannot run without its own key, so
# none of the 8 can be taken offline. Offline signers must be SEPARATE keypairs added to the set,
# which grows n and moves the threshold with it:
#
#   set                    | n  | threshold | fleet holds | one SSH compromise wins?
#   -----------------------|----|-----------|-------------|-------------------------
#   8 fleet only           | 8  | 6         | 8           | YES
#   8 fleet + 2 offline    | 10 | 7         | 8           | YES
#   8 fleet + 3 offline    | 11 | 8         | 8           | YES  <- exactly reaches it
#   8 fleet + 4 offline    | 12 | 9         | 8           | NO   <- what this file uses
#
# Four is the smallest number that puts the fleet's own 8 keys BELOW the threshold, so compromising
# every production node no longer yields control of miner discovery.
#
# The 4 offline keys were generated on an operator machine that is not a pool node, one `--data-dir`
# each (the path is otherwise fixed at `~/.ghost/node.key` and repeated runs overwrite it). Their
# private keys have never been on the fleet and must never be copied to it.
#
# KEY HYGIENE — learned the hard way
#
# `node.key` is 44 bytes: a 32-byte SECRET key plus a 12-byte PoW proof. `xxd`/`cat` on it prints the
# secret. A first set of 4 keys was discarded and regenerated because its contents were rendered to a
# terminal and captured. Back these up by COPYING the file, or by writing the hex to a file with
# output redirection — never by displaying it. Verify a backup with `cmp`, which is silent on success.
#
# ADDING AN OPERATOR
#
# A new operator's node id is added by publishing a list that includes it, signed by >=6 of the
# current set. The set is not fixed for all time — only this FIRST list is, and only for miners who
# never update. As independent operators join, the fleet's own share of the set falls below the
# threshold on its own, which is how the single-operator trust root is meant to dissolve.
#
# PROVENANCE OF THESE IDS
#
# Read on 2026-08-03 from each node itself:
#
#   ssh <node> "sudo -u ghost /opt/ghost/bin/ghost-pool --config /etc/ghost/pool.toml --show-identity"
#
# That is the ONLY method to trust. Do not read a node's own id from the `peers` table — it returns
# the most-recently-seen peer instead, which produced a table that was wrong for vm1 and vm7. Do not
# infer one by elimination either; vm6's was deduced that way and only confirmed later.
